# Physical continuous JOC validation v1

Status: hardware validation plan for issue #143. This document selects the first physical proof chain; it is not itself physical evidence.

## Goal

Prove a continuous real-hardware path from authorized TV/player eARC output through Aurora's already-proven moving-JOC software path to a synchronous physical 7.1.4-class output:

`TV/player -> eARC -> IEC61937 E-AC-3 JOC -> Aurora -> 12-channel 48 kHz physical output`

The first test must reuse the checksum-pinned carrier already proven in PRs #140 and #142:

`0219a241559de5231f31c6093072740ff9fe0657b3354541bc6838ef2d5e5be0`

Do not start this gate with DRM-service debugging.

## Selected v1 chain

### Ingress

Use the existing Lindy 38368 / SiI9437 setup and the project-specific logic-level audio tap that previously demonstrated:

`eARC -> Pi 5 I2S slave -> IEC61937 type 0x15 -> raw E-AC-3`

Important: the logic-level tap is an Aurora test modification around the SiI9437 path; it is not a connector or feature exposed by Lindy's stock product. The vendor product itself is an HDMI eARC extractor.

The Raspberry Pi 5 is the first host because that ingress path has already been demonstrated. The Pi is not an Aurora architectural dependency. If the full Harletty/Omniphony 12-channel path cannot sustain realtime on the Pi, only the host-compute role moves to the existing N100 Linux target; Aurora core contracts must not change to accommodate the board.

### Output transport

Use one miniDSP MCHStreamer Lite as the only USB audio clock domain and load its TDM16 firmware at 48 kHz.

Vendor-documented TDM16 pin assignment on J1:

| J1 pin | TDM16 role |
| --- | --- |
| 1 | output channels 1-8 |
| 3 | output channels 9-16 |
| 9 | MCLK |
| 10 | BCLK |
| 11 | GND |
| 12 | FSYNC |

The MCHStreamer documentation states that each active TDM data line carries eight channels and that TDM16 supports 44.1/48/88.2/96 kHz. Aurora's first physical gate uses 48 kHz only.

### DAC stage

Use two synchronized eight-channel TDM DAC stages, preferably PCM3168A-class for the first proof:

- DAC A consumes MCHStreamer output channels 1-8.
- DAC B consumes MCHStreamer output channels 9-16.
- Both share the same MCLK, BCLK and FSYNC generated by the MCHStreamer.
- Aurora uses only the first 12 channels for 7.1.4; output slots 13-16 remain unused during this gate.

The PCM3168A is an active TI 6-in/8-out codec whose DAC supports 8 channels, TDM, 48 kHz operation and external serial clocks. Exact carrier-board wiring, logic levels, control mode, reset sequencing and analog-output stage must be verified before electrical testing. Selecting the codec class here is not a claim that an arbitrary marketplace board is pin-compatible or validated.

No amplifier or speaker is required for the first electrical proof. The DAC outputs may be measured directly or looped back into measurement inputs. Amplifier, speaker and acoustic validation remain later gates.

## Why this chain

This is the smallest trustworthy first proof because it:

- reuses the only ingress path Aurora has already physically demonstrated;
- keeps raw IEC61937 E-AC-3 JOC intact and forbids re-encoding;
- uses one synchronous USB audio device instead of aggregating independent sound cards;
- provides 16 synchronous output slots, enough for 7.1.4 plus margin;
- lets Aurora preserve its hardware-agnostic source/render/output contracts;
- separates physical transport proof from amplifier/speaker/acoustic work.

## Required evidence

### Gate A — physical ingress

Record and preserve:

- exact source carrier SHA-256;
- capture start/end monotonic timestamps;
- IEC61937 burst count;
- data type for every burst, requiring `0x15`;
- payload/frame continuity;
- capture reset/drop counters;
- raw payload identity against the known carrier wherever transport framing permits byte-exact comparison.

Any discontinuity, non-`0x15` burst, hidden transcoding or unaccounted payload mutation fails the gate.

### Gate B — Aurora render on physical host

Feed the physical capture into the unchanged moving-JOC validation path and require:

- Harletty admission without decoder reset;
- non-zero moving object metadata;
- 12-channel, 48 kHz Omniphony output;
- temporal render diversity;
- no fallback to 5.1, bed-only rendering or synthetic upmix.

### Gate C — physical 12-channel output

For the MCHStreamer/ALSA path record:

- USB VID/PID and ALSA card/device identity;
- negotiated channel count and sample format;
- sample rate = 48 kHz;
- ALSA buffer and period configuration;
- expected output frames and actual output frames;
- xrun/underrun/overrun counters or log markers;
- CPU load and scheduler/priority configuration;
- clock/drift observations for the full carrier duration.

Pass requires one synchronous device exposing at least 12 channels, exact frame preservation and zero unexplained xruns.

### Gate D — electrical/channel mapping

Verify all 12 assigned channels electrically. Preserve the exact Aurora layout-to-physical-slot map used by the test rather than assuming a channel order in this document.

Where a loopback return path is available, measure round-trip latency. Only a physical loopback result may be called measured latency; configured, nominal or calculated values must be labeled accordingly.

## Fail-closed rules

- No re-encoding of the pinned carrier.
- No substitution of a 5.1 decode plus upmix for object decoding.
- No aggregation of independently clocked USB output devices for the acceptance result.
- No claim that a clean TDM logic trace alone proves DAC/analog output.
- No claim that DAC activity alone proves authored object-position correctness.
- No DRM bypass or protected-media extraction.
- No Dolby certification/conformance claim from this validation.

## Stop conditions and fallback

1. If Pi 5 cannot sustain the full renderer at realtime, preserve the ingress adapter and move compute to the N100 Linux host through a lossless/raw transport adapter. Do not weaken render or pacing gates.
2. If the selected DAC carrier boards cannot be made to share the MCHStreamer clock domain cleanly, replace only the DAC stage. Do not replace the single-clock output principle.
3. If a hardware failure prevents exact evidence, mark the gate failed/incomplete; do not substitute a software simulation.

## Completion boundary

Issue #143 may close only after one full-duration run proves:

`physical eARC capture -> raw JOC preservation -> Aurora moving-object render -> synchronous physical 12-channel output`

with captured evidence for continuity, frame counts, channel activity, timing/clock health and xruns.

After that, the next independent gate is legitimate streaming-service Atmos compatibility, followed by final DAC/amplifier/speaker architecture and wireless synchronization.
